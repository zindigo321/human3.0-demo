# Human 3.0 对话工作台

一个中文、单用户、本地运行的个人反思工具。通过单问题访谈整理四象限证据，支持修改历史回答建立分支、修订判断、调整规则、保留评估版本和导出可编辑报告。层级是暂定观察，不代表人的价值，也不提供人格总分或临床诊断。

项目不依赖固定盘符或安装目录。构建、浏览器及报告验证结果见 `docs/CHECKLIST.md` 与 `docs/REVIEW.md`；未完成的检查会明确标出。

本地测试：33 项领域及接口测试、8 项浏览器测试通过。没有配置真实模型凭据，真实模型服务及判断质量尚未验证。

## 安装与启动

安装 Node.js 22.12 或以上版本（包含 npm）。Windows、macOS 和 Linux 都可以使用下方的终端命令；目前实际运行验收环境为 Windows。首次安装需要连接 npm 下载依赖。

从 GitHub 获取 `human3.0-demo`：点击仓库的 **Code → Download ZIP** 并解压，或运行 `git clone`。然后在含有 `package.json` 的项目文件夹中打开终端。ZIP 解压后的文件夹通常名为 `human3.0-demo-main`，名称和存放位置可以自行选择。

```sh
npm ci
npm run build
npm start
```

打开 [本地工作台](http://127.0.0.1:4310)，保持启动终端运行。停止服务时按 `Ctrl+C`。之后再次使用只需在同一目录运行 `npm start`。

Windows 也可以双击项目内的 `start-workbench.cmd`。它会在缺少依赖或构建文件时自动准备，然后启动本地服务。桌面快捷方式属于各自电脑的设置，不是运行项目的必要条件。

服务器只监听 `127.0.0.1`；可用 `PORT` 环境变量或项目 `.env` 更改默认端口。安装完成后，演示模式不需要模型密钥，也不连接外部模型服务。使用真实 AI 时，每位使用者填写自己的服务配置。

仓库需要保留 `package-lock.json`，用于安装固定依赖；`node_modules/`、`dist/`、`work/` 和 `.env` 由 `.gitignore` 排除。下载源码后执行上述安装与构建命令即可生成所需文件。

修改源码后重新运行 `npm run build` 再启动；也可直接运行 `npm run dev`，它会先构建再启动本地服务。第一版不提供开发热更新。

## 使用流程

1. 新建会话，从理想生活开始回答。每次提交后查看下一问；可以跳过、暂停、恢复或选择主题。
2. 在四象限卡片查看依据。点击证据回到原回答，留意“待了解”及尚待核实的解释。
3. 编辑任一历史回答。应用从该位置创建新分支；左侧可切回原分支查看旧回答及后续。
4. 重新分析得到新的评估版本。修改判断时填写原因，并编辑证据、优先级或行动安排；旧模型建议和旧修订保留。
5. 修改规则后保存新版本。旧评估显示需要重新分析；原始来源说明与自定义规则分开保留。
6. 按需要生成暂定报告、编辑内容并导出 DOCX；定期导出 JSON 保留整个数据集及版本关联。

- `samples/demo-session.json`：通过实际界面导出的虚构访谈备份，可用“导入备份”加载。导入会替换当前数据集，请先导出自己的备份。

也可点击“打开虚构演示”，在当前数据集中新增演示会话。示例不包含真实个人访谈或服务端密钥。

## 演示和真实模型

没有模型密钥时为明确标注的演示模式：本地编辑、分支、规则、备份和报告仍可使用。演示追问使用主题与回答片段生成，不自动赋予 L1–L3，不冒充真实语义评估。演示案例均为虚构。

真实模型通过服务端环境变量 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_NAME` 配置。将 `.env.example` 复制为项目根目录下的 `.env`，填入自己的配置后重启服务；服务会读取该文件，仓库忽略 `.env`。接口须兼容 `/chat/completions` 及 JSON 对象返回格式。密钥不进入前端、会话备份或常规日志。接入真实模型后，提交的有效回答及规则会发送到配置的服务。

只有提交回答或明确重新分析才触发请求；打字、保存和普通视图切换不调用模型。失败或取消不会伪造成功结果，用户可以明确重试。真实服务的连接、凭据、模型质量与费用须以实际服务为准；本地替身测试不能证明真实模型质量。

## 数据与恢复

数据自动保存于当前浏览器、当前站点地址的本地存储。刷新会恢复，同一项目换浏览器或地址不会自动迁移。保存失败时保留现有内存数据并提示，可先导出 JSON。

JSON 导入先校验结构及所有关联，通过后替换当前数据集；无效备份不会损坏现有数据。导入其他文件前建议导出自己的备份。浏览器存储和 JSON 备份包含访谈原文且未加密，请自行保管。第一版建议在一个标签页编辑。

## 测试

```powershell
npm run build
npm test
npm run test:e2e
```

运行浏览器测试前，先在另一个终端启动应用并保持运行。Windows 默认使用本机 Edge（`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`），无需另外下载浏览器；路径不同可设置 `TEST_BROWSER_PATH` 为兼容浏览器的实际可执行文件路径。测试地址默认 `http://127.0.0.1:4310`，可用 `TEST_BASE_URL` 修改；具体设置见 `playwright.config.ts`。测试使用虚构数据、隔离浏览器环境和本地服务；外部模型可在适配器边界由测试替身替换，实际业务代码仍被执行。

## 已知限制

演示模式不能替代真实访谈评估。结构和引文校验能阻止格式错误及伪造引用，但不能证明推断本身正确。第一版四象限证据限定为对应主题回答，理想生活与优先级回答用于计划；如某段经历涉及另一领域，可切到该主题补充。该限制是产品选择，不是原模型要求。

浏览器存储有容量限制，不支持多设备同步或多标签冲突合并。单次分析最多 200 条回答，分析及报告请求最多 2 MB，JSON 导入最多 5 MB；超过限制时需缩小数据集。

示例 DOCX 的文字、表格和全部连续预览已检查。当前环境没有可用的标准文档渲染器，未在 Microsoft Word 或 LibreOffice 中验证自动分页；浏览器文档预览不能保证这些软件中的精确布局。详细验证范围见 `docs/REVIEW.md`。
